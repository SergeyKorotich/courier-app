Курьер — смены
PWA-приложение для водителей-курьеров: запись смен, отрезков маршрута, перевозок врачей и справочник врачей/клиник. Работает офлайн, данные синхронизируются с Google Таблицей через Apps Script Web App.

Как это устроено
text
Телефон (PWA, GitHub Pages)
   │  index.html + app.js + sw.js
   │  localStorage: справочники, открытая смена, офлайн-очередь
   ▼
Apps Script Web App (api.gs)
   │  doGet — выдаёт справочники + последние 500 смен
   │  doPost — принимает пакеты записей (shift/segment/doctor/…)
   ▼
Google Таблица
   Drivers, Shifts, SegmentsAPI, DoctorS, DoctorsRef,
   Points, MedPoints, InterPoints, SyncLog, Врачи, Клиники
Офлайн-режим. Ввод работает без сети: смена хранится в localStorage, отправки падают в очередь и уходят автоматически при появлении сети. Неотправленные записи видны счётчиком на дашборде. Пакет, который сервер отклонил, ретраится до 3 раз, после чего пропускается с сообщением «сообщите старшему» — один сбойный пакет не блокирует очередь.

Аутентификация. ФИО + PIN по листу Drivers. Роль «старший» открывает кнопку «Статистика всех водителей». Сохранённый PIN при появлении сети тихо перепроверяется; разлогина нет — открытая смена не теряется.

Восстановление смены. Незавершённая смена переживает перезапуск приложения и показывает сводку: авто, число отрезков, последний отрезок и одометр в его конечной точке. Смена другого водителя в чужом телефоне не открывается — предлагается сообщить старшему.

Справочники. Врачи и клиники ведутся на листах «Врачи» и «Клиники», правки с телефона уходят в таблицу и применяются локально сразу.

Конфликт с упрощённой версией (листовая форма). Проект существует в двух вариантах: листовая форма (Form/Data/Segments/Doctor) и PWA. Листы не пересекаются; перевозки врачей PWA пишутся на отдельный лист DoctorS, чтобы не смешиваться с Doctor упрощённой версии.

Логика маршрута (важно)
В отрезках точки хранятся как введены, но нормализуются к виду «Первая Заглавная»: «ижевск», «Ижевск», «ИЖЕВСК» → Ижевск; «офис» → Офис. Ижевск на отрезках не подменяется Офисом.
При закрытии смены маршрут собирается функцией compressRoute: подряд идущие одинаковые точки схлопываются, соседние Офис/Ижевск считаются одной точкой, крайние Ижевск (начало и конец маршрута) заменяются на Офис — смена всегда стартует и финиширует в Офисе. Пример: отрезки Офис→Ижевск, Ижевск→Бодья, Бодья→Ижевск, Ижевск→Офис дают маршрут Офис, Бодья, Офис.
Точка старта маршрута — «Откуда» первого отрезка смены, даже если отрезок записан без перемещения (Офис → Офис).
Тип отрезка: междугородний отрезок с участием Офиса или «точка в точку» — Город, иначе Трасса. Городские отрезки — всегда Город.
Одометр и пробег
Водитель вводит показание одометра в точке «Куда» (с начала смены); километраж отрезка считается как разница с предыдущим показанием.
В сообщении после записи отрезка «всего» = последнее введённое показание одометра, без пересчётов.
Одометр конца смены = одометр начала + сумма километражей отрезков; он автоматически подставляется в начало следующей смены.
Врачи
Перевозка врача: врач, пункт (только из MedPoints), назначенное и фактическое время. Врач — из справочника DoctorsRef.
В колонке «врач» смены: пункт показывается один раз за смену, врачи одного пункта — через запятую, новый пункт — с новой строки; отклонение от назначенного времени подсвечивается: опоздание красным, «раньше» зелёным (rich text через colorizeDoctorCell).

Деплой
Фронтенд (GitHub Pages). Правки в index.html/app.js/sw.js → commit + push. При изменении статики обязательно поднять версию кэша (CACHE) в sw.js — без этого телефоны продолжат работать на старой версии.

Бэкенд (Apps Script). Правки в api.gs → сохранить → «Развернуть → карандаш → Новая версия → Развернуть». URL веб-приложения прописан в API_URL в app.js (при смене URL обновить и он).

Разовая настройка. В таблице выполнить apiSetup() — создаст листы с нужными заголовками. На листе Drivers должны быть колонки ФИО и PIN. Однократная нормализация регистра точек в справочниках — скрипт normalizePointCase() (Points / InterPoints / MedPoints).

Листы таблицы
Drivers — ФИО, автомобиль, госномер, роль, PIN.
Shifts — одна строка на завершённую смену: даты, одометры, пробег, маршрут, заправка, продолжительность, врачи, статус.
SegmentsAPI — отрезки смены (откуда/куда/одометр/километраж/тип).
DoctorS — перевозки врачей PWA (дата, врач, пункт, назначенное и фактическое время, recordId — ключ уникальности, shiftId).
Doctor — лист упрощённой версии, PWA его не трогает.
Врачи, Клиники — справочники с контактами и ссылками на маршруты.
Points / MedPoints / InterPoints — городские, мед- и междугородние точки для подсказок.
DoctorsRef — имена врачей для подсказок в поле «Врач».
SyncLog — журнал синхронизации.
Конвенции данных
Даты — строка ГГГГ-ММ-ДД; время — чч:мм.
Ключи записей — timestamp-random, генерируются на клиенте.
Точки — «Первая Заглавная» (Ижевск, Можга, Офис); сравнения точек в коде регистронезависимые, поэтому старые записи «ОФИС» из таблицы считаются той же точкой, что и Офис.
ФИО врачей — естественный регистр; ФИО — главный ключ водителя: правки авто и переименование ищут строки по нормализованному ФИО.
Дубликаты при повторной отправке отсекаются сервером по id записи (у перевозок врача — по recordId).
Известные особенности
Исторические смены в Shifts могут содержать маршруты со старым форматом («ОФИС» капсом, «Ижевск» в конце) — новые записи пишутся правильно; при необходимости возможна разовая миграция колонки «маршрут».
Смена автомобиля в открытой смене запрещена после первого отрезка — одометр начала привязан к конкретной машине.
